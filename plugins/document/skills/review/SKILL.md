# 문서 점검

이 스킬은 이미 쓴 글을 `/document:write`의 작성 원칙에 맞게 점검하고 고친다. 파일을 받으면 파일을 직접 고치고, 붙여 넣은 글을 받으면 고친 글을 돌려준다.

## 목차

1. 기계 점검
2. 원칙 점검
3. 맞춤법과 문체 점검
4. 결과 보고

## 1. 기계 점검

점검 스크립트로 기계가 판별할 수 있는 위반을 먼저 찾는다. 붙여 넣은 글은 파일 경로 대신 `-`를 주고 표준 입력으로 넘긴다.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/review/scripts/lint.py" <파일 경로>
```

스크립트가 잡는 항목은 다음과 같다.

| 분류 | 잡는 내용 |
| --- | --- |
| 강조 | 굵게와 기울임 표시 |
| 기호 | 화살표, 줄표, 가운뎃점, 이모지 같은 장식 기호 |
| 혼용 | 한글에 붙은 영어 단어, 한국어로 바꿀 수 있어 보이는 영어 소문자 단어 |
| 참조 | 내용 없이 참조만 안내하는 문장 |
| 빈 줄 | 문단, 제목, 목록 사이의 빈 줄 누락과 빈 줄 겹침 |
| 목차 | 긴 글의 목차 누락, 번호 없는 제목 |

코드 블록, 인라인 코드, 링크 주소는 점검하지 않는다. 나쁜 예시를 보여 줘야 하면 인라인 코드나 코드 블록으로 감싼다.

혼용 항목은 제품명이나 고유명사를 잘못 잡을 수 있다. 대신할 한국어가 정말 없으면 그대로 두고, 명령어나 식별자라면 인라인 코드로 감싼다.

## 2. 원칙 점검

스크립트가 판별하지 못하는 원칙은 글을 읽으며 직접 확인한다.

1. 문서와 각 절의 첫 문장이 결론인가. 아니면 결론 문장을 찾아 맨 앞으로 옮긴다.
2. 처음 보는 사람이 읽고 이해할 수 있는가. 설명 없는 약어와 내부 별칭을 풀어 쓴다.
3. 참조만 걸고 내용이 빠진 곳이 있는가. 원문을 읽고 필요한 내용을 옮겨 쓴다.
4. 지워도 뜻이 바뀌지 않는 문장이 있는가. 반복, 끝맺음 요약, 분량을 늘리는 수식어를 지운다.
5. 문단마다 하나의 생각만 담고 분명하게 끝나는가. 흐린 마무리 문장을 고친다.

고친 뒤 글이 원래보다 길어졌다면 무엇이 늘었는지 확인한다. 참조 내용을 옮겨서 늘어난 것이 아니라면 다시 줄인다.

## 3. 맞춤법과 문체 점검

마지막으로 k-skill 플러그인의 다음 두 스킬로 교정한다. k-skill은 `document` 플러그인의 의존성이라 함께 설치되어 있다.

| 스킬 | 쓰는 목적 |
| --- | --- |
| `k-skill:korean-spell-check` | 맞춤법과 띄어쓰기 교정 |
| `k-skill:korean-humanizer` | 번역체와 기계가 쓴 듯한 문체 교정 |

두 스킬이 고친 결과도 1장 점검 스크립트를 다시 통과해야 한다.

## 4. 결과 보고

사용자에게 다음을 짧게 알린다.

1. 고친 위반의 분류별 건수
2. 원칙 점검에서 크게 바꾼 부분과 그 이유
3. 판단이 필요해 고치지 않고 남긴 부분
4. 마지막 점검 스크립트 결과
