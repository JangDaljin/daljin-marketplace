# 문서 작성 원칙

이 스킬은 사람이 읽는 문서를 쓸 때 지킬 원칙과 작성 순서를 정한다. 원칙은 모두 지킨다. 원칙끼리 부딪히면 읽는 사람이 더 빨리 이해하는 쪽을 고른다.

## 목차

1. 작성 원칙
2. 작성 순서
3. 고쳐 쓰기 예시

## 1. 작성 원칙

### 1.1 두괄식으로 쓴다

문서, 절, 문단 모두 결론을 첫 문장에 둔다. 배경과 근거는 결론 뒤에 붙인다. 첫 문장만 읽어도 무엇을 말하려는지 알 수 있어야 한다.

### 1.2 사람이 읽기 편하게 쓴다

독자가 처음 보는 사람이라고 가정하고 쓴다. 작성자 머릿속에만 있는 약어, 내부 별칭, 맥락을 설명 없이 쓰지 않는다. 문장은 말로 읽었을 때 자연스러워야 한다. 기계가 만든 목록이나 필드 나열처럼 보이는 글은 문장으로 풀어 쓴다.

### 1.3 참조 내용은 직접 가져와 쓴다

`자세한 내용은 어디를 참조하라`로 끝내지 않는다. 독자가 알아야 할 내용을 원문에서 가져와 문서 안에 직접 쓴다. 출처가 필요하면 가져온 내용 뒤에 출처를 덧붙이되, 출처만 남기고 내용을 비우지 않는다.

### 1.4 특수 기호를 쓰지 않는다

화살표, 줄표, 별표 장식, 체크 표시, 이모지, 가운뎃점, 꺾쇠 괄호 같은 장식용 기호를 쓰지 않는다. 기호가 하던 역할은 말로 푼다. 예를 들어 `A → B`는 "A에서 B로", `A·B`는 "A와 B"로 쓴다. 제목, 목록, 표, 코드 블록처럼 문서 구조를 만드는 마크다운 문법은 쓸 수 있다.

### 1.5 한국어와 영어를 섞지 않는다

기본은 한국어로 쓴다. 대신할 한국어가 없는 용어만 영어 원어를 쓴다. "API를 호출한다"는 괜찮지만 `API를 call한다`는 쓰지 않는다. "배포한다"로 충분한 곳에 `deploy한다`를 쓰지 않는다. 제품명, 명령어, 코드, 식별자는 원래 표기를 그대로 쓴다.

### 1.6 짧고 명료하게 쓴다

길게 쓴다고 좋은 글이 아니다. 핵심을 분명히 잡으면 글이 길 필요가 없다. 분량을 채우려고 글자를 늘리지 않는다. 같은 말을 반복하지 않고, 앞에서 한 말을 끝에서 다시 요약하지 않는다. 지워도 뜻이 그대로인 문장은 지운다.

### 1.7 굵게나 기울임으로 강조하지 않는다

특정 단어만 굵게 하거나 기울여서 강조하지 않는다. 중요한 내용은 문장의 앞자리에 두거나 별도 문장으로 써서 드러낸다.

### 1.8 문단을 명료하게 끝낸다

한 문단에는 하나의 생각만 담는다. 문단의 마지막 문장은 그 문단의 요지를 마무리한다. "등등", "여러 가지가 있다", "추후 보완한다"처럼 흐리게 끝내지 않는다.

### 1.9 문단 사이는 한 줄 띄운다

문단을 나눌 때는 빈 줄을 하나 넣는다. 제목 아래, 목록과 표의 앞뒤에도 빈 줄을 하나 넣는다. 빈 줄을 두 줄 이상 겹쳐 넣지 않는다.

### 1.10 긴 글에는 숫자 목차를 쓴다

500자 이상인 글은 긴 글로 보고 첫 문단 다음에 목차를 둔다. 글자 수는 공백을 포함해 세고, 코드 블록과 문서 머리말은 세지 않는다. 목차와 제목에는 1, 2, 3 같은 숫자를 붙인다. 하위 절은 1.1, 1.2처럼 번호를 이어 붙인다. 목차의 번호와 제목은 본문 제목과 똑같이 맞춘다.

## 2. 작성 순서

### 2.1 독자와 목적을 한 문장으로 정한다

쓰기 전에 "누가 읽고, 읽은 뒤 무엇을 할 수 있어야 하는가"를 한 문장으로 정한다. 이 문장이 정해지지 않으면 사용자에게 먼저 묻는다.

### 2.2 결론을 먼저 쓴다

문서 전체의 결론을 첫 문단에 쓴다. 이어서 각 절의 결론 문장을 먼저 적어 뼈대를 만든다.

### 2.3 참조 자료를 모아 내용으로 옮긴다

문서에 필요한 외부 내용은 직접 읽고 요지를 옮겨 쓴다. 자료 종류에 따라 다음 도구를 쓴다.

| 자료 | 도구 |
| --- | --- |
| 라이브러리, 프레임워크 공식 문서 | `context7` MCP |
| PDF, Word, PowerPoint, Excel 파일 | `markitdown` MCP의 `convert_to_markdown` |
| 웹 페이지 | WebFetch |
| Confluence, Jira | mcp-atlassian |
| 개인 지식베이스 | `daljin-kb:search` 스킬 |

### 2.4 본문을 쓰고 줄인다

뼈대에 맞춰 본문을 쓴 뒤, 지워도 뜻이 바뀌지 않는 문장과 단어를 지운다.

### 2.5 점검한다

마크다운 파일로 저장했다면 점검 스크립트를 돌려 기계로 잡을 수 있는 위반을 먼저 고친다.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/review/scripts/lint.py" <파일 경로>
```

스크립트가 잡지 못하는 두괄식, 장황함, 참조 내용 누락은 1장 원칙을 기준으로 직접 확인한다. 전체 점검 절차는 `/daljin-doc:review` 스킬이 맡는다.

## 3. 고쳐 쓰기 예시

고치기 전 문장이다.

```text
이번 배포에서는 여러 가지 변경사항이 있었는데, 자세한 내용은 PR을 참조하시면 되고, 가장 중요한 건 **인증 방식 변경**입니다 → 기존 토큰은 만료됩니다.
```

고친 문장이다.

```text
이번 배포로 인증 방식이 바뀌어 기존 토큰은 모두 만료된다. 사용자는 다시 로그인해야 한다.

바뀐 점은 두 가지다. 첫째, 토큰 유효 기간이 30일에서 7일로 줄었다. 둘째, 갱신 토큰을 새로 발급한다.
```

결론을 앞에 두었고, 참조 대신 내용을 옮겼고, 굵게와 화살표를 없앴다.
