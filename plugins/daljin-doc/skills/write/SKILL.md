# 문서 작성 원칙

사람이 읽는 문서를 쓸 때 지킬 원칙과 쓰는 순서예요.
원칙은 모두 지켜요.
원칙끼리 부딪히면 읽는 사람이 더 빨리 이해하는 쪽을 골라요.

## 목차

1. 작성 원칙
2. 쓰는 순서
3. 고쳐 쓰기 예시

## 1. 작성 원칙

### 1.1 두괄식

문서, 절, 문단 모두 결론을 첫 문장에 둬요.
배경과 근거는 결론 뒤에 붙여요.
첫 문장만 읽어도 무엇을 말하려는지 알 수 있어야 해요.

### 1.2 사람이 읽기 편한 글

처음 보는 사람이 읽는다고 생각하고 써요.
쓴 사람만 아는 약어, 내부 별칭, 배경은 풀어서 써요.
소리 내어 읽었을 때 자연스러워야 해요.
기계가 뽑은 목록처럼 보이는 글은 사람이 말하듯 풀어 써요.

### 1.3 부드러운 말투

문장은 "~해요", "~예요"처럼 부드러운 존댓말로 끝내요.
제목, 목록 항목, 표 칸은 "설치 방법"처럼 짧은 명사형으로 끝내도 돼요.

### 1.4 한 줄에 한 가지

무언가를 알려 주려고 쓰는 글은 한 줄에 한 가지만 써요.
다음 이야기는 줄을 바꿔서 써요.
나열할 것이 여러 개면 목록으로 써요.
마크다운에서는 줄만 바꾸면 화면에서 한 문단으로 이어 붙어요.
줄마다 떨어져 보여야 하는 곳은 목록으로 쓰거나 빈 줄을 넣어요.
수필이나 긴 설명처럼 길게 풀어 쓰는 글은 이 원칙에서 빼요.

### 1.5 참조할 것은 직접 옮기기

"자세한 것은 어디를 보세요"로 끝내지 않아요.
읽는 사람이 알아야 할 부분은 원문에서 가져와 문서 안에 직접 써요.
출처가 필요하면 옮긴 글 뒤에 출처를 덧붙여요.
출처만 남기고 설명을 비워 두지 않아요.

### 1.6 특수 기호 쓰지 않기

화살표, 줄표, 별표 장식, 체크 표시, 이모지, 가운뎃점, 꺾쇠 괄호 같은 기호를 쓰지 않아요.
기호가 하던 역할은 말로 풀어요.
화살표 대신 "A에서 B로"라고 쓰고, 가운뎃점 대신 "A와 B"라고 써요.
제목, 목록, 표, 코드 블록처럼 문서의 틀을 만드는 마크다운 문법은 써도 돼요.

### 1.7 코드 표기 쓰지 않기

단어를 백틱으로 감싸는 코드 표기를 쓰지 않아요.
제품 이름, 파일 이름, 명령어 이름도 그냥 글자로 써요.
읽는 사람이 그대로 입력해야 하는 명령은 코드 블록으로 따로 보여 줘요.

### 1.8 한국어와 영어 섞지 않기

기본은 한국어로 써요.
대신할 한국어가 없는 용어만 영어 원어를 써요.
"API를 호출해요"는 괜찮아요.
영어 동사에 "하다"나 "되다"를 붙여 쓰지는 않아요.
제품 이름과 명령어는 원래 표기 그대로 써요.

### 1.9 짧고 명료하게

길게 쓴다고 좋은 글이 되지 않아요.
핵심을 분명히 잡으면 글이 길 필요가 없어요.
분량을 채우려고 글자를 늘리지 않아요.
같은 말을 되풀이하지 않고, 앞에서 한 말을 끝에서 다시 요약하지 않아요.
지워도 뜻이 그대로인 문장은 지워요.

### 1.10 강조 표시 쓰지 않기

특정 단어만 굵게 하거나 기울여서 강조하지 않아요.
중요한 것은 문장 맨 앞에 두거나 따로 한 줄로 써서 드러내요.

### 1.11 문단의 분명한 끝맺음

한 문단에는 생각 하나만 담아요.
문단의 마지막 문장으로 그 문단의 요지를 마무리해요.
"등등", "여러 가지가 있어요", "나중에 보완할게요"처럼 흐리게 끝내지 않아요.

### 1.12 빈 줄

문단을 나눌 때는 빈 줄을 하나 넣어요.
제목 아래와 목록, 표의 앞뒤에도 빈 줄을 하나 넣어요.
빈 줄을 두 줄 넘게 겹쳐 넣지 않아요.

### 1.13 긴 글의 숫자 목차

500자가 넘는 글은 첫 문단 다음에 목차를 둬요.
글자 수는 공백까지 세고, 코드 블록과 문서 머리말은 세지 않아요.
목차와 제목에는 1, 2, 3 같은 숫자를 붙여요.
하위 절은 1.1, 1.2처럼 번호를 이어 붙여요.
목차의 번호와 제목은 본문 제목과 똑같이 맞춰요.

## 2. 쓰는 순서

### 2.1 독자와 목적 정하기

쓰기 전에 누가 읽고, 읽은 뒤 무엇을 할 수 있어야 하는지 한 문장으로 정해요.
이 문장을 정할 수 없으면 사용자에게 먼저 물어봐요.

### 2.2 결론부터 쓰기

문서 전체의 결론을 첫 문단에 써요.
이어서 각 절의 결론 문장을 먼저 적어 뼈대를 만들어요.

### 2.3 참조 자료 옮기기

문서에 필요한 외부 자료는 직접 읽고 요지를 옮겨 써요.
자료 종류에 따라 다음 도구를 써요.

| 자료 | 도구 |
| --- | --- |
| 라이브러리와 프레임워크 공식 문서 | context7 MCP |
| PDF, Word, PowerPoint, Excel 파일 | markitdown MCP |
| 웹 페이지 | WebFetch |
| Confluence와 Jira | mcp-atlassian |
| 개인 지식베이스 | daljin-kb의 search 스킬 |

### 2.4 쓰고 줄이기

뼈대에 맞춰 본문을 써요.
다 쓰면 지워도 뜻이 바뀌지 않는 문장과 단어를 지워요.

### 2.5 점검하기

마크다운 파일로 저장했다면 점검 스크립트를 돌려요.
기계로 잡을 수 있는 위반부터 고쳐요.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/review/scripts/lint.py" <파일 경로>
```

길게 풀어 쓰는 글이면 한 줄에 한 문장 검사를 건너뛰어요.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/review/scripts/lint.py" --long-form <파일 경로>
```

두괄식, 장황함, 참조 누락은 스크립트가 잡지 못해요.
이 셋은 1장 원칙을 기준으로 직접 확인해요.
전체 점검 절차는 daljin-doc의 review 스킬에 있어요.

## 3. 고쳐 쓰기 예시

고치기 전 글이에요.

```text
이번 배포에서는 여러 가지 변경사항이 있었는데, 자세한 내용은 PR을 참조하시면 되고, 가장 중요한 건 **인증 방식 변경**입니다 → 기존 토큰은 만료됩니다.
```

고친 글이에요.

```text
이번 배포로 인증 방식이 바뀌어서 기존 토큰은 모두 만료돼요.
다시 로그인해야 해요.

바뀐 점은 두 가지예요.

1. 토큰 유효 기간이 30일에서 7일로 줄었어요.
2. 갱신 토큰을 새로 발급해요.
```

결론을 앞에 두고, 참조 안내 대신 바뀐 점을 직접 옮겼어요.
굵게 표시와 화살표는 없앴어요.
한 줄에 한 가지만 담았어요.
