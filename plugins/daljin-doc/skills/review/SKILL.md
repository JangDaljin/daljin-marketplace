# 문서 점검

이미 쓴 글을 daljin-doc의 write 스킬에 있는 작성 원칙에 맞게 점검하고 고치는 스킬이에요.
파일을 받으면 파일을 직접 고쳐요.
붙여 넣은 글을 받으면 고친 글을 돌려줘요.

## 목차

1. 기계 점검
2. 원칙 점검
3. 맞춤법과 문체 점검
4. 결과 보고

## 1. 기계 점검

점검 스크립트로 기계가 가려낼 수 있는 위반부터 찾아요.

    python3 "${CLAUDE_PLUGIN_ROOT}/skills/review/scripts/lint.py" <파일 경로>

붙여 넣은 글은 파일 경로 자리에 하이픈 하나를 주고 표준 입력으로 넘겨요.
길게 풀어 쓰는 글이면 --long-form 옵션을 붙여 한 줄에 한 문장 검사를 건너뛰어요.

스크립트가 잡는 항목은 다음과 같아요.

| 분류 | 잡는 것 |
| --- | --- |
| 말투 | "~한다", "~이다"로 끝나는 문장 |
| 한 줄 | 한 줄에 여러 문장을 넣은 곳 |
| 백틱 | 백틱으로 감싼 단어와 코드 블록 표시 |
| 강조 | 굵게와 기울임 표시 |
| 기호 | 화살표, 줄표, 가운뎃점, 이모지 같은 장식 기호 |
| 혼용 | 영어 동사에 "하다"나 "되다"를 붙인 말 |
| 참조 | 필요한 설명 없이 참조만 안내하는 문장 |
| 빈 줄 | 제목, 목록, 표 앞뒤의 빈 줄 누락과 빈 줄 겹침 |
| 목차 | 500자가 넘는 글의 목차 누락과 번호 없는 제목 |

네 칸 들여쓴 줄과 링크 주소는 점검하지 않아요.
나쁜 예시를 보여 줘야 하면 네 칸 들여써요.

## 2. 원칙 점검

스크립트가 가려내지 못하는 원칙은 글을 읽으며 직접 확인해요.
지적받은 곳만 고치지 말고 문서 전체를 처음부터 다시 봐요.
위반이 없다는 스크립트 결과가 좋은 글이라는 뜻은 아니에요.

1. 읽는 사람이 이 문서로 할 일에 필요 없는 절과 설명은 통째로 지워요.
2. 누구나 볼 수 있는 문서라면 내부 정보가 들어 있지 않은지 봐요.
3. 문서와 각 절의 첫 문장이 결론이 아니면 결론 문장을 맨 앞으로 옮겨요.
4. 설명 없는 약어와 내부 별칭은 처음 보는 사람도 알 수 있게 풀어 써요.
5. 참조만 걸어 두고 설명이 빠진 곳은 원문을 읽고 필요한 부분을 옮겨 써요.
6. 되풀이, 끝맺음 요약, 분량만 늘리는 꾸밈말처럼 지워도 뜻이 그대로인 문장은 지워요.
7. 생각이 둘 이상 섞인 문단은 나누고, 흐리게 끝나는 마무리 문장은 고쳐요.
8. 영어 이름 뒤의 조사는 daljin-doc을처럼 읽는 소리에 맞춰요.

고친 글이 원래보다 길어졌다면 무엇이 늘었는지 확인해요.
참조할 부분을 옮겨서 늘어난 게 아니라면 다시 줄여요.

## 3. 맞춤법과 문체 점검

마지막으로 k-skill 플러그인의 두 스킬로 교정해요.
k-skill은 daljin-doc을 설치할 때 함께 설치돼요.

| 스킬 | 쓰는 목적 |
| --- | --- |
| k-skill의 korean-spell-check | 맞춤법과 띄어쓰기 교정 |
| k-skill의 korean-humanizer | 번역투와 기계가 쓴 듯한 문체 교정 |

두 스킬로 고친 글도 1장의 점검 스크립트를 다시 통과해야 해요.

## 4. 결과 보고

사용자에게 다음을 짧게 알려요.

1. 고친 위반의 분류별 건수
2. 원칙 점검에서 크게 바꾼 곳과 그 이유
3. 판단이 필요해서 고치지 않고 남긴 곳
4. 마지막 점검 스크립트 결과
