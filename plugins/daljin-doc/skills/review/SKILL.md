# 문서 점검

사람이 읽는 문서를 `/daljin-doc:write`의 작성 원칙에 맞게 점검하고 고친다. 파일을 받으면 직접 고치고, 붙여 넣은 글이면 고친 글을 돌려준다.

`SKILL.md`, `CLAUDE.md`, 에이전트 프롬프트처럼 에이전트가 읽는 지시문은 점검 대상이 아니다. 요청받아도 작성 원칙을 적용하지 말고 대상이 아니라고 알린다.

## 1. 먼저 전체를 다시 본다

지적받은 곳만 고치지 않는다. 문서 전체를 처음부터 읽고 다음을 먼저 판단한다.

1. 독자가 누구이고 이 문서로 무엇을 하는가. 공개 문서인가, 사용자 본인만 보는가.
2. 각 절이 그 할 일에 필요한가. 필요 없는 절은 통째로 지운다.
3. 공개 문서라면 내부 정보(비공개 저장소 구조, 인증 방법 등)가 있는가. 있으면 지운다.

## 2. 기계 점검

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/review/scripts/lint.py" [--long-form] <파일 경로>
```

- 붙여 넣은 글은 경로 대신 `-`를 주고 표준 입력으로 넘긴다.
- 길게 풀어 쓰는 글이면 `--long-form`으로 한 줄 한 문장 검사를 건너뛴다.
- 네 칸 들여쓴 줄과 링크 주소는 점검하지 않는다.

| 분류 | 잡는 것 |
| --- | --- |
| 말투 | "~한다", "~이다"로 끝나는 문장 |
| 한 줄 | 한 줄에 문장 여러 개 |
| 코드 표기 | 인라인 백틱, 코드 블록 펜스 |
| 강조 | 굵게, 기울임 |
| 기호 | 화살표, 줄표, 가운뎃점, 이모지 등 |
| 혼용 | 영어 동사 + "하다"/"되다" |
| 참조 | 설명 없이 참조만 안내하는 문장 |
| 빈 줄 | 제목, 목록, 표 앞뒤 빈 줄 누락, 빈 줄 겹침 |
| 목차 | 500자 넘는 글의 목차 누락, 번호 없는 제목 |

"위반 없음"은 좋은 글이라는 뜻이 아니다. 1장과 3장 판단을 대신하지 않는다.

## 3. 원칙 점검

스크립트가 못 잡는 것을 직접 확인한다.

- 문서와 절의 첫 문장이 결론인가.
- 설명 없는 약어, 내부 별칭이 있는가.
- 참조만 걸고 설명이 빠진 곳이 있는가.
- 되풀이, 끝맺음 요약, 분량만 늘리는 꾸밈말이 있는가.
- 문단에 생각이 둘 이상 섞였거나 흐리게 끝나는가.
- 영어 이름 뒤 조사가 읽는 소리와 맞는가.

고친 글이 원래보다 길어졌으면 무엇이 늘었는지 확인하고, 참조를 옮긴 게 아니면 다시 줄인다.

## 4. 맞춤법과 문체

k-skill(의존성으로 함께 설치됨)의 두 스킬로 마무리한다. 고친 결과도 2장 스크립트를 다시 통과해야 한다.

- `k-skill:korean-spell-check`: 맞춤법, 띄어쓰기
- `k-skill:korean-humanizer`: 번역투, 기계가 쓴 듯한 문체

## 5. 결과 보고

짧게 알린다: 지운 절과 이유, 크게 바꾼 곳, 판단이 필요해 남긴 곳, 마지막 스크립트 결과.
