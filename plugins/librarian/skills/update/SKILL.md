## KB 세션 반영 (daljin-knowledge-base)

이번 세션에서 나온 내용 중 **재사용 가치가 있는 것**을 개인 지식베이스에 규칙대로 정리해 넣는다.

- `$ARGUMENTS`가 있으면 그 주제/범위로 한정한다 (예: `프록시 설정 정정`).
- 현재 작업 디렉토리가 아니라 아래에서 찾은 **KB 루트**(`<KB>`)에 쓴다.

### 0. KB 위치 확인과 최신화 (항상)

스크립트 경로의 `<이 SKILL.md가 있는 폴더>`를 실제 설치된 이 파일의 폴더 절대 경로로 바꿔 실행한다.

```bash
sh "<이 SKILL.md가 있는 폴더>/../../scripts/kb-root.sh"
```

첫 줄이 `<KB>`다. 스크립트가 실패하면 로컬 작업 복제본이 없는 것이다. 사용자에게 `git@github.com:JangDaljin/daljin-knowledge-base.git`을 `~/development/daljin-knowledge-base`에 복제할지 묻고, 승인받으면 복제한 뒤 다시 확인한다.

쓰기 전에 `<KB>`에서 `git pull`로 main을 최신화한다. 이미 커밋되지 않은 변경이 있으면 다른 세션의 작업일 수 있으니 건드리지 않고, 커밋할 때 이번 반영분만 넣는다.

### 1. 규칙 먼저 로드 (항상)

작업 전 KB의 최신 규칙을 읽어 그대로 따른다. 아래 파일이 단일 출처다:
- `<KB>/AGENTS.md` (있으면), `<KB>/CLAUDE.md`
- `<KB>/knowledge/CLASSIFICATION.md` (분류·front-matter·피드백 분류·압축)
- `<KB>/knowledge/COMMIT-GUIDE.md` (커밋 규칙)
- `<KB>/knowledge/INDEX.md` (현재 서가 목록)

규칙이 이 스킬 설명과 다르면 **KB 파일의 규칙이 우선**이다.

### 2. 반영 후보 추리기

이번 세션 대화에서 다음을 후보로 뽑는다:
- 새로 알게 된 지식 / 정리한 내용 (특정 프로젝트·주제)
- 내린 결정, 받은 피드백, 번복된 결정
- 기존 KB 문서의 사실 오류·최신화가 필요한 부분 (정정 후보)

세션에만 유효한 잡담·일회성 작업은 제외한다.

### 3. 사용자 승인 (필수 — 임의로 쓰지 않는다)

후보를 **표로 정리해 사용자에게 제시**하고 승인받는다. 각 후보에 대해:
- 무엇을 / 어느 서가(분류 경로)에 / 새 문서인지 기존 갱신인지
- 결정·피드백이면 운영(루트 FEEDBACK)인지 콘텐츠(서가 FEEDBACK)인지

승인된 항목만 진행한다. 애매하면 어디에 둘지 물어본다.
(결정 ID를 언급할 땐 ID만 말고 그 내용도 함께 보여준다.)

### 4. 반영

승인된 항목마다:
1. **분류 결정** → 해당 서가 폴더(`knowledge/work/...` 또는 `knowledge/personal/...`)에 문서 추가/갱신. 서가가 없으면 `CLASSIFICATION.md` 규칙대로 신설.
2. **front-matter** 부여/갱신: `분류` / `태그` / `갱신`(오늘 날짜, 절대표기).
3. **INDEX.md** 해당 서가에 한 줄 등재(신규 문서 시).
4. **피드백/결정**: 콘텐츠 → 그 서가의 `FEEDBACK.md`(없으면 생성, 서가 접두사), 운영·구조 → 루트 `knowledge/FEEDBACK.md`. 번복은 기존 항목 상태만 바꾸고(지우지 않음) 새 항목을 위에 추가·링크.
5. **PROGRESS.md** 맨 위에 이번 반영 이력 한 항목 추가.
6. 파일이 길면(~400줄/30항목) `CLASSIFICATION.md`의 **압축 규칙** 적용 후 `🗜 압축:` 근거를 남긴다.

### 5. 커밋

`COMMIT-GUIDE.md`대로 커밋한다:
- 제목 **30자 미만**, 유형 라벨(`입수/개정/재분류/색인/운영/폐기`) + 요약
- 본문은 **서가별 분류**로 정리, 관련 결정은 `FEEDBACK: [ID]`
- 이번 반영과 관계없는 변경은 커밋에 넣지 않는다.
- **커밋 후 push 는 반드시 사용자에게 "지금 KB 변경사항을 push 할까요?"라고 묻고 승인받은 뒤에만 한다.**

### 마무리

무엇을 어느 서가에 넣었고 어떤 커밋을 만들었는지 사용자에게 짧게 요약한다.
