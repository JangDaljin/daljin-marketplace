# 드럼 비트

유튜브 주소나 오디오 파일에서 드럼만 분리하고, 스틱 클릭으로 카운트인과 드럼 앞 빈 구간의 박을 채운 드럼 비트 음원을 만든다. 내려받기, 분리(htdemucs_ft), 박 찾기(beat_this), 클릭 합성, 규칙 검사는 `scripts/drumbeat.py` 가 한다.

스크립트 경로의 `<이 SKILL.md가 있는 폴더>`를 실제 설치된 이 파일의 폴더 절대 경로로 바꿔 실행한다. 스크립트는 `uv run --script` 로 실행한다. uv 가 파일 머리말의 의존성(torch, beat_this 등)을 설치하므로 가상환경을 따로 만들지 않는다.

## 1. 반드시 지킬 규칙

사용자가 정한 규칙이다. 예외는 없다.

1. 맨 앞에는 카운트인 4박이 들어간다. 드럼이 곡 처음부터 나와도, 곡 첫 박보다 먼저(픽업) 나와도 드럼 앞에 4박이 온전히 있어야 한다. 픽업이면 카운트인을 4박씩 앞당긴다.
2. 카운트인 뒤부터 드럼 첫 타격 직전 박까지 매 박 클릭을 넣는다. 발라드처럼 드럼이 곡 중간에 들어와도 그 앞을 비워 두지 않는다.

정리하면 "드럼 앞 카운트인 4박 + 드럼이 나올 때까지 빈 곳은 전부 클릭"이다. 카운트인은 곡의 박자와 상관없이 4박이다.

스크립트는 결과 JSON 의 `rules` 로 두 규칙을 검사한다. `rules.ok` 가 false 면 결과 파일을 만들지 않고 종료 코드 4로 끝난다. 이때는 5장의 박 고치기 옵션으로 다시 돌리고, 그래도 안 되면 `rules` 값과 함께 사용자에게 보고하고 멈춘다. 규칙을 어긴 결과를 넘기지 않는다.

## 2. 요청 확인

아래를 확인한다. 사용자가 이미 말한 것은 다시 묻지 않고, 빠진 것만 한 번에 묻는다.

- 입력: 유튜브 영상 주소 하나 또는 로컬 오디오 파일 경로. 재생목록 주소면 영상 하나를 골라 달라고 한다.
- 곡 이름: 결과 파일 이름 `<가수 - 제목>(드럼).mp3` 에 쓴다. 사용자가 말하지 않았으면 영상 정보로 "가수 - 제목" 을 추정해 질문에 함께 넣어 확인받는다. 영상 정보는 아래 명령으로 본다. 영상 제목의 `[MV]`, `(Official Audio)` 같은 꾸밈말은 뺀다.

  ```bash
  yt-dlp --no-playlist --print "%(channel)s | %(title)s | %(duration)s초" "<주소>"
  ```

- 저장 형식: 사용자가 형식을 말하지 않았으면 매번 묻는다. 첫 선택지는 기본값 mp3 320kbps 다.

| 형식 | 옵션 | 설명 |
| --- | --- | --- |
| mp3 320kbps | `--format mp3` (기본) | 연습용으로 충분한 품질, 작은 용량 |
| wav | `--format wav` | 무손실 16비트 |
| flac | `--format flac` | 무손실 압축 |

묻지 않는 것:

- 저장 위치: 기본 `~/Music/musician/` 이다. 사용자가 위치를 말할 때만 `--out` 으로 준다.
- 분리 모델: 드럼 품질을 위해 `htdemucs_ft` 로 고정한다.
- 카운트인과 클릭 여부: 1장 규칙대로 항상 넣는다. 클릭 없는 원본 드럼만 원한다고 분명히 말하면 이 스킬 대신 `musician:stem-split` 스킬의 `--stem drums` 로 처리한다.

## 3. 도구 점검

`uv` 가 있어야 한다. 없으면 설치 승인을 받은 뒤 설치한다(macOS `brew install uv`, Windows `winget install astral-sh.uv`, Linux `curl -LsSf https://astral.sh/uv/install.sh | sh`).

```bash
uv run --script "<이 SKILL.md가 있는 폴더>/scripts/drumbeat.py" check
```

- 처음 실행하면 uv 가 torch 등 의존성을 내려받아 몇 분 걸릴 수 있다. 사용자에게 미리 알린다.
- 종료 코드 0 이면 다음 단계로 간다.
- 종료 코드 2 면 결과 JSON 의 `missing` 과 `install` 을 사용자에게 보여 주고, 승인을 받은 뒤 그 명령으로 설치한다. 승인 없이 설치하지 않는다.
- 필요한 도구는 demucs 와 ffmpeg 이고, 유튜브 주소면 yt-dlp 와 JS 런타임(deno 또는 node)이 더 필요하다.

## 4. 실행

```bash
uv run --script "<이 SKILL.md가 있는 폴더>/scripts/drumbeat.py" run "<주소 또는 파일>" --name "가수 - 제목" --format mp3
```

| 옵션 | 뜻 |
| --- | --- |
| `--name "가수 - 제목"` | 결과 파일 이름. 없으면 영상 제목이나 파일 이름 |
| `--format`, `--bitrate` | 저장 형식과 mp3 비트레이트. 기본 mp3, 320 |
| `--out <폴더>` | 결과 폴더. 기본 `~/Music/musician` |
| `--tempo-factor 0.5` 또는 `2` | BPM 이 두 배나 절반으로 잡혔을 때 고친다 |
| `--shift N` | 마디 첫 박을 N 박 뒤로(음수면 앞으로) 옮긴다 |
| `--max-minutes <분>` | 이보다 긴 영상은 거부한다. 기본 20, 0 이면 제한 없음 |

실행 환경에 따라 다음을 지킨다.

- 오래 걸린다. htdemucs_ft 분리는 기본 모델의 4배쯤 걸리고 박 찾기는 CPU 로 한다. 에이전트가 명령을 백그라운드로 돌릴 수 있으면 백그라운드로 돌리고 끝나면 보고한다. 그럴 수 없으면 명령 제한 시간을 15분 이상으로 준다.
- 네트워크와 작업 폴더 밖 쓰기가 필요하다. 유튜브 내려받기, uv 의존성 설치, 처음 쓰는 demucs 모델과 beat_this 체크포인트 내려받기, `~/Music/musician` 과 캐시 쓰기가 그렇다. Codex 처럼 샌드박스가 이를 막는 환경이면 이 명령 하나를 권한 상승(네트워크 허용, 작업 폴더 밖 쓰기)으로 승인 요청한다.
- 단계마다 결과를 남기고 다시 실행하면 재사용한다. `source.wav` 는 stem-split 과 같은 폴더, 같은 파일이라 서로 다시 내려받지 않는다.

## 5. 결과 확인과 박 고치기

진행 기록은 표준 오류로, 결과는 표준 출력 마지막 줄의 JSON 한 줄로 나온다.

| 종료 코드 | 뜻 | 할 일 |
| --- | --- | --- |
| 0 | 성공 | 아래처럼 확인하고 보고한다 |
| 1 | 실행 실패 | `error` 와 `hint` 를 따른다. 같은 오류가 반복되면 표준 오류 마지막 부분과 함께 보고하고 멈춘다 |
| 2 | 도구 없음 | 3장처럼 설치 승인을 받고 설치한 뒤 다시 실행한다 |
| 3 | 입력 문제 | 사용자에게 `error` 를 전하고 다시 묻는다. 길이 제한이면 처리할지 묻고 `--max-minutes 0` 으로 다시 실행한다 |
| 4 | 규칙 검사 실패 | 1장대로 박을 고쳐 다시 돌리고, 안 되면 보고하고 멈춘다 |

성공하면 결과 JSON 에서 다음을 확인한다.

- `bpm`, `beats_per_bar`: 곡을 아는 경우 BPM 이 두 배나 절반으로 잡혔는지 본다. 그렇다면 `--tempo-factor` 로 고쳐 다시 돌린다.
- `drum_entry_sec`, `count_in_sec`, `intro_click_count`: 드럼이 몇 초에 들어오고 그 앞에 클릭이 몇 개 들어갔는지 본다.
- `warnings`: 그대로 사용자에게 전한다. 특히 "앞부분 N마디를 같은 템포로 이어 붙였다", "템포가 일정하지 않다" 는 클릭이 원곡과 어긋날 수 있다는 뜻이다.
- `drum_profile`: 마디 안 박 위치별 킥과 스네어 세기다. 보통 4박 곡은 킥이 1, 3박, 스네어가 2, 4박에서 크다. 킥이 2, 4박에서 크고 스네어가 1, 3박에서 크게 뒤집혀 있으면 마디 첫 박이 한 박 어긋났을 수 있다. 곡마다 패턴이 달라 이것만으로 정하지 말고, 사용자에게 확인용 파일을 들어 보게 한 뒤 `--shift 1` 이나 `--shift -1` 로 고친다.

박을 고쳐 다시 돌려도 내려받기, 분리, 박 찾기는 재사용하므로 금방 끝난다.

## 6. 결과 보고

다음을 짧게 보고한다.

- 결과 파일(`output`)과 확인용 파일(`check`) 경로
- BPM, 박자, 드럼 시작 시각, 카운트인 4박 뒤에 이어진 클릭 수
- `warnings` 내용
- 확인용 파일(원곡에 같은 클릭을 붙인 것)을 들어 보고 클릭이 원곡 박에 맞는지 확인해 달라는 요청. 어긋나면 5장 옵션으로 고친다
- 결과물은 개인 연습과 학습용이며 다시 배포하지 않는다는 안내 한 줄

결과 폴더 구조:

```
~/Music/musician/<제목>-<영상 ID>/
  source.wav                    내려받은 원곡 (stem-split 과 같이 쓴다)
  stems/htdemucs_ft/drums.wav   분리한 드럼
  beats.json                    박과 마디 첫 박
  analysis.json                 BPM, 클릭 위치, 규칙 검사 결과
  <가수 - 제목>(드럼).mp3         드럼 비트 결과
  check_원곡+카운트인.mp3         원곡에 같은 클릭을 붙인 확인용
```

로컬 파일을 넣으면 폴더 이름이 `<파일 이름>` 이고, 원본을 `source.wav` 로 바꿔 둔다.

## 7. 하지 않는 일

- 재생목록이나 여러 영상 일괄 처리
- 클릭 소리나 카운트인 박 수 바꾸기
- 템포, 키 변경 같은 음원 편집
- 사용자 승인 없는 도구 설치
