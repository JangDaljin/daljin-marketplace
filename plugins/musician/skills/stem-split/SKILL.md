# 악기 분리

유튜브 주소나 오디오 파일을 받아 원하는 악기만 뽑거나 뺀 음원을 만든다. 내려받기, 분리, 결과 정리는 `scripts/stem.py` 가 한다. 이 스킬은 무엇을 묻고, 어떻게 실행하고, 무엇을 보고하는지를 정한다.

스크립트 경로의 `<이 SKILL.md가 있는 폴더>`를 실제 설치된 이 파일의 폴더 절대 경로로 바꿔 실행한다. `python3` 이 없는 환경(Windows 등)이면 `python` 이나 `py` 로 실행한다.

## 1. 요청 확인

아래를 확인한다. 사용자가 이미 말한 것은 다시 묻지 않고, 빠진 것만 한 번에 묻는다.

- 입력: 유튜브 영상 주소 하나 또는 로컬 오디오 파일 경로. 재생목록 주소면 영상 하나를 골라 달라고 한다.
- 악기: `references/instruments.md` 표로 `--stem` 값을 정한다. 말이 없으면 묻고, 선택지에 "전부(보컬, 드럼, 베이스, 나머지)"를 넣는다. 표에 없는 악기(신스, 현악, 관악 등)는 따로 뽑을 수 없고 `other` 에 섞여 나온다고 알린 뒤 `other` 를 받을지 묻는다.
- 뽑기와 빼기: "드럼만", "보컬만"은 뽑기, "MR", "반주만", "드럼 빼고"는 빼기(`--minus`)다. 어느 쪽인지 애매하면 묻는다.
- 저장 형식: 사용자가 형식을 말하지 않았으면 매번 묻는다. 첫 선택지는 기본값 mp3 320kbps 다.

| 형식 | 옵션 | 설명 |
| --- | --- | --- |
| mp3 320kbps | `--format mp3` (기본) | 연습과 공유에 충분한 품질, 작은 용량 |
| wav | `--format wav` | 무손실 16비트. 편집 프로그램에 넣을 때 |
| flac | `--format flac` | 무손실 압축. ffmpeg 필요 |

다른 비트레이트를 원하면 `--bitrate` 로 준다.

묻지 않는 것:

- 품질: 기본 모델(htdemucs)로 한다. 사용자가 "더 깨끗하게", "고품질로"라고 할 때만 `--quality high`(htdemucs_ft, 4배쯤 느림)를 쓴다.
- 저장 위치: 기본 `~/Music/musician/` 이다. 사용자가 위치를 말할 때만 `--out` 으로 준다.

## 2. 도구 점검

```bash
python3 "<이 SKILL.md가 있는 폴더>/scripts/stem.py" check
```

- 종료 코드 0 이면 다음 단계로 간다.
- 종료 코드 2 면 결과 JSON 의 `missing` 과 `install` 을 사용자에게 보여 주고, 설치해도 되는지 승인을 받은 뒤 그 명령으로 설치한다. 승인 없이 설치하지 않는다.
- 로컬 파일만 처리할 때는 `demucs` 만 있으면 된다(flac 저장은 ffmpeg 도 필요). 유튜브 주소는 `yt-dlp`, `ffmpeg`, JS 런타임(deno 또는 node)이 더 필요하다. 유튜브 내려받기는 yt-dlp 2025.11.12 부터 JS 런타임 없이는 동작하지 않는다.

## 3. 실행

```bash
# 유튜브에서 드럼만 mp3 320kbps 로
python3 "<이 SKILL.md가 있는 폴더>/scripts/stem.py" run "<주소>" --stem drums

# 보컬을 뺀 MR 을 wav 로
python3 "<이 SKILL.md가 있는 폴더>/scripts/stem.py" run "<주소>" --stem vocals --minus --format wav

# 로컬 파일에서 기타와 베이스
python3 "<이 SKILL.md가 있는 폴더>/scripts/stem.py" run "<파일 경로>" --stem guitar --stem bass
```

| 옵션 | 뜻 |
| --- | --- |
| `--stem <이름>` | 뽑을 악기. 여러 번 줄 수 있다. 없으면 모델의 모든 악기 |
| `--minus` | `--stem` 하나를 뺀 나머지를 `no_<이름>` 으로 만든다 |
| `--quality high` | htdemucs_ft 로 분리한다. 기타와 피아노에는 적용되지 않는다 |
| `--format`, `--bitrate` | 저장 형식과 mp3 비트레이트. 기본 mp3, 320 |
| `--out <폴더>` | 결과 폴더. 기본 `~/Music/musician` |
| `--keep-all` | 요청하지 않은 악기도 `_all/` 에 남긴다 |
| `--max-minutes <분>` | 이보다 긴 영상은 거부한다. 기본 20, 0 이면 제한 없음 |

실행 환경에 따라 다음을 지킨다.

- 오래 걸린다. 기본 모델로 GPU 에서는 곡 길이의 3분의 1쯤, CPU 에서는 곡 길이의 절반에서 1.5배쯤 걸린다. 처음 쓰는 모델은 내려받는 시간이 더 든다. 에이전트가 명령을 백그라운드로 돌릴 수 있으면 백그라운드로 돌리고 끝나면 보고한다. 그럴 수 없으면 명령 제한 시간을 10분 이상으로 준다.
- 네트워크와 작업 폴더 밖 쓰기가 필요하다. 유튜브 내려받기, 처음 쓰는 모델 내려받기, `~/Music/musician` 과 모델 캐시 쓰기가 그렇다. Codex 처럼 샌드박스가 이를 막는 환경이면 이 명령 하나를 권한 상승(네트워크 허용, 작업 폴더 밖 쓰기)으로 승인 요청한다. 내려받기와 분리가 한 명령이라 승인은 한 번이면 된다.
- 같은 영상을 다시 처리하면 이미 받은 `source.wav` 를 다시 쓰고 내려받지 않는다. 분리는 매번 새로 하고, 같은 이름의 결과 파일은 덮어쓴다.

## 4. 실패 처리

진행 기록은 표준 오류로, 결과는 표준 출력 마지막 줄의 JSON 한 줄로 나온다. `error` 와 `hint` 를 읽고 종료 코드에 따라 처리한다.

| 종료 코드 | 뜻 | 할 일 |
| --- | --- | --- |
| 2 | 도구 없음 | 2장처럼 설치 승인을 받고 설치한 뒤 다시 실행한다 |
| 3 | 입력 문제 | 사용자에게 `error` 를 전하고 다시 묻는다. 길이 제한에 걸렸으면 처리할지 묻고, 승인하면 `--max-minutes 0` 으로 다시 실행한다 |
| 1 | 실행 실패 | `hint` 를 따른다. 내려받기 실패는 yt-dlp 업데이트를 승인받아 한 번 다시 시도한다. 같은 오류가 반복되면 표준 오류 마지막 부분과 함께 보고하고 멈춘다 |

연령 제한, 지역 제한, 비공개 영상은 받지 못한다. 로그인 쿠키를 쓰는 우회는 하지 않는다.

## 5. 결과 보고

결과 JSON 을 읽어 다음을 짧게 보고한다.

- 결과 파일 경로(`outputs`)와 폴더
- 사용한 모델, 저장 형식, 걸린 시간
- `notes` 의 품질 안내. 기타와 피아노, `other` 의 한계를 숨기지 않는다
- `notes` 에 GPU 에서 실패해 CPU 로 분리했다는 안내가 있으면 그대로 전하고, 안내된 명령으로 demucs 를 다시 설치할지 묻는다. 결과는 같고 속도만 달라지므로 설치는 승인받았을 때만 한다
- 다른 악기가 필요하면 `--keep-all` 이나 다른 `--stem` 으로 다시 실행할 수 있고, 다시 내려받지 않는다는 점
- 결과물은 개인 연습과 학습용이며 다시 배포하지 않는다는 안내 한 줄

결과 폴더 구조:

```
~/Music/musician/<제목>-<영상 ID>/
  source.wav    내려받은 원곡 (다시 실행할 때 재사용, 필요 없으면 지워도 된다)
  meta.json     주소, 제목, 길이, 모델, 형식, 결과 파일 목록
  drums.mp3     요청한 악기 (빼기면 no_<악기>.mp3)
  _all/         --keep-all 을 줬을 때만, 나머지 악기
```

로컬 파일을 넣으면 폴더 이름이 `<파일 이름>` 이고 `source.wav` 는 만들지 않는다.

## 6. 하지 않는 일

- 재생목록이나 여러 영상 일괄 처리
- 템포, 키 변경 같은 음원 편집
- demucs 가 아닌 다른 분리 도구 사용
- 사용자 승인 없는 도구 설치
